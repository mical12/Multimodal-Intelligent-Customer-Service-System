# RAG 路由实验总结

## 目标

这轮实验主要解决一个问题：一些本该进入产品专家的手册类问题，被意图识别路由到了普通客服。

核心思路是：当规则无法直接命中产品时，不只依赖产品摘要，而是用全局 RAG 从所有手册中召回候选片段，再把候选片段作为纯文本证据交给大模型判断。

## 最终结论

建议采用 `global_rag` 作为当前主路由模式。

当前正式模式：

```text
规则命中 -> 全局 RAG 候选片段辅助判断 -> 普通客服
```

配置位置：`config.yaml`

```yaml
agents:
  intent:
    routing_mode: "global_rag"  # summary 或 global_rag
    global_rag_assist:
      enabled: true
      manual_count: 10
      snippets_per_manual: 2
      global_top_k: 80
      snippet_max_chars: 420
```

完整 400 道意图识别结果：

| 方案 | 结果 | 说明 |
|---|---:|---|
| 旧摘要模式，强保守 prompt | 364/400 | 许多泛问法问题被打到 customer |
| 摘要 + 全局 RAG 混合链路 | 396/400 | 摘要 LLM 修复 32 道，全局 RAG 补 4 道 |
| 全局 RAG 模式 | 396/400 | 规则命中 314 道，全局 RAG 补 36 道，customer 50 道 |

全局 RAG 和混合链路总分相同，但全局 RAG 模式更干净、可解释，也更符合当前问题形态。

## 400 道全局 RAG 模式结果

结果文件：`intent_400_global_rag_mode.csv`

```text
总数: 400
正确: 396
错误: 4
```

路由来源：

```text
规则命中产品手册: 314
全局RAG候选片段辅助命中产品手册: 36
普通客服: 50
```

剩余 4 个错误都属于“泛问题被相似手册吸走”：

| id | 预期 | 实际 |
|---:|---|---|
| 196 | Active Noise Canceling Truly Wireless Earphones | VR头显 |
| 295 | Camera Installation Guide | Digital, single-lens reflex, AF/AE camera |
| 414 | Camera Installation Guide | Digital, single-lens reflex, AF/AE camera |
| 433 | Color Television | Digital, single-lens reflex, AF/AE camera |

这 4 个影响很小，暂时不建议继续为它们加复杂规则，否则可能伤到全局 RAG 召回回来的 36 个正例。

## 摘要模式为什么之前会保守

之前摘要 LLM 的 prompt 里有一条强保守约束：

```text
问题没有明确产品线索，即使提到 troubleshooting、safety、maintenance，也返回 customer。
```

这会导致很多英文泛问法被压到普通客服，例如 landline、boat、camera、TV 相关问题。

去掉这条后，摘要 LLM 能把一批问题拉回专家；但从完整实验看，全局 RAG 单独模式也能达到同样的 396/400。

## 36 道 fallback 实验

最初针对 `rag_route_36_customer_fallback.csv` 中 36 个被路由到普通客服的问题，测试了“全局 RAG 候选片段 + 大模型判断”。

候选手册数量对比：

| 候选手册数 | 专家路由 | 严格产品命中 | 预期产品进入候选 |
|---:|---:|---:|---:|
| 3 | 36/36 | 28/36 | 32/36 |
| 5 | 36/36 | 28/36 | 34/36 |
| 10 | 36/36 | 31/36 | 35/36 |

结论：

- top3 不够，主要是正确手册有时排在第 4 或第 5。
- top5 比 top3 明显改善候选覆盖。
- top10 在严格产品命中上继续提升，当前采用 10 本候选手册更稳。

## 混合检索实验

只看 top3 召回覆盖：

| 方法 | top3 覆盖 |
|---|---:|
| BM25 | 29/36 |
| Embedding | 32/36 |
| RRF 融合 | 31/36 |
| 归一化加权，0.6 sparse + 0.5 dense | 32/36 |

不同权重进一步对比：

| 策略 | top3 覆盖 |
|---|---:|
| dense only | 33/36 |
| sparse 0.1 + dense 0.9 | 32/36 |
| sparse 0.2 + dense 0.8 | 32/36 |
| sparse 0.3 + dense 0.7 | 33/36 |
| sparse 0.4 + dense 0.6 | 31/36 |
| sparse 0.5 + dense 0.5 | 30/36 |
| sparse 0.6 + dense 0.5 | 30/36 |

结论：

BM25 对专有词可能有帮助，但对 `safety precautions`、`turn on`、`set up` 这类泛问法噪声较大。当前不建议引入混合检索作为主路由方案。

## 当前代码状态

`model.py` 已把意图识别拆成两个层次：

- `IntentAgent`：负责路由流程编排。
- `GlobalRagIntentRouter`：负责全局 RAG 检索、候选聚合、片段 prompt、产品名归一化。

这样 `IntentAgent` 不再承载所有细节，后续切换 `summary` / `global_rag` 更清楚。
